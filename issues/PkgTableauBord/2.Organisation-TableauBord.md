# Issue #2 : Organisation Modulaire et Configuration Dynamique du Tableau de Bord (Multi-Rôles, Typologie de Composants & Pages de Détail)

## 📌 1. Contexte & Problématique

Actuellement, les vues Blade du tableau de bord pédagogique ([formateur/index.blade.php](file:///c:/AppServer/solicode-lms/modules/PkgTableauBord/resources/views/formateur/index.blade.php), [apprenant/index.blade.php](file:///c:/AppServer/solicode-lms/modules/PkgTableauBord/resources/views/apprenant/index.blade.php), [responsable/index.blade.php](file:///c:/AppServer/solicode-lms/modules/PkgTableauBord/resources/views/responsable/index.blade.php)) intègrent en dur (*hardcodé*) les directives `@include` pour afficher les indicateurs didactiques et leurs volets associés.

Ce fonctionnement rigide engendre plusieurs limites :
1. **Absence de paramétrage fin par acteur** : Impossible de configurer l'affichage ou non d'un indicateur pour les trois acteurs (`formateur`, `admin`, `apprenant`), ainsi que pour le rôle `root` (qui doit avoir un accès total).
2. **Couplage non formalisé entre Indicateur et Panels** : Un indicateur et ses panels sont étroitement liés. Si un indicateur n'est pas affiché ou désactivé pour un rôle, **ses panels opérationnels associés ne doivent sous aucun prétexte être affichés de manière orpheline**.
3. **Contrôle de l'accès à la Page de Détail (`show_detail`)** : La possibilité d'accéder à la page d'analyse granulaire d'un indicateur doit pouvoir être autorisée ou interdite par profil.
4. **Maintenance et extensibilité** : Tout ajout ou modification d'indicateur impose de retoucher manuellement et synchroniquement l'ensemble des contrôleurs et gabarits.

## 🎯 2. Objectifs de la Demande

1. **Création du fichier centralisé `config/dashboard.php`** :
   - Référencer le catalogue exhaustif des 9 indicateurs didactiques.
   - Définir pour chaque acteur (`apprenant`, `formateur`, `admin`, `root`) :
     - `enabled` (bool) : Activation globale de l'indicateur pour l'acteur (interrupteur maître).
     - `show_card` (bool) : Affichage de la carte synthétique dans la grille supérieure.
     - `show_panel` (bool) : Affichage du volet opérationnel/métier associé dans le corps de page.
     - `show_detail` (bool) : Autorisation d'accès et visibilité du lien vers la page d'analyse détaillée (`admin.PkgTableauBord.indicateurs.*`).
   - **Règle de couplage strict** : Si un indicateur est désactivé (`enabled => false` ou `show_card => false`), **ses panels associés ne sont pas affichés**, car ils en dépendent directement.
   - **Rôle `root`** : Affichage et accès garantis à $100\%$ des Cards, Panels et Pages de détail.
2. **Phase de validation dédiée** :
   - Dès la création du fichier `config/dashboard.php`, marquer un temps d'arrêt obligatoire pour permettre au développeur de vérifier et d'ajuster les réglages avant l'adaptation des services, contrôleurs et vues Blade.
3. **Orchestration de l'affichage via la couche Service** :
   - Résoudre la configuration selon l'utilisateur connecté dans [TableauBordService.php](file:///c:/AppServer/solicode-lms/modules/PkgTableauBord/Services/TableauBordService.php).
   - Bloquer l'accès aux pages de détail dans [IndicateurDetailController.php](file:///c:/AppServer/solicode-lms/modules/PkgTableauBord/Controllers/IndicateurDetailController.php) si `show_detail` est `false` pour l'acteur.

## 🏛️ 3. Architecture & Typologie des Composants

Chaque indicateur du tableau de bord se décline en **3 niveaux de restitution visuelle et fonctionnelle**, régis par la configuration :

| Type | Dénomination | Paramètre Config | Emplacement UI | Rôle & Contenu |
| :--- | :--- | :--- | :--- | :--- |
| **Type 1** | **`Card`** *(KPI Card)* | `show_card` | Grille supérieure (`grid-cols-*`) | Résumé synthétique : valeur clé, badge docimologique, seuils, bouton vers la page de détail (si `show_detail => true`). |
| **Type 2** | **`Panel`** *(Panel Opérationnel)* | `show_panel` | Corps du dashboard (pleine largeur sous la grille) | Action immédiate, console FIFO, listings ciblés, alertes critiques. **Strictement conditionné à l'activation de l'indicateur**. |
| **Type 3** | **`Detail`** *(Page d'Analyse)* | `show_detail` | Route dédiée (`indicateurs.{nom}`) | Audit exhaustif granulaire, historique, formules de calcul, filtres avancés. |

## 🔬 5. Règle de Couplage & Résolution Technique

Dans `TableauBordService` (méthode de résolution) :
```text
Pour chaque indicateur configuré pour le rôle actif :
  1. Si (enabled == false) => Ignorer complètement (ni Card, ni Panel, ni Detail).
  2. Si (requires_session == true ET isSessionFormation == false) => Ignorer.
  3. Si (show_card == true) => Ajouter au tableau $dashboardCards.
  4. Si (show_panel == true ET show_card == true [ou exception explicite file/intervention]) => Ajouter au tableau $dashboardPanels.
     * Règle d'or : Si l'indicateur est masqué (show_card == false) sans statut opérationnel dédié, son panel n'est jamais rendu.
  5. Si (show_detail == false) => Masquer le lien "Voir Détail" sur la Card et interdire l'accès HTTP dans IndicateurDetailController.
```
